# Demand Validation Agent

## Назначение

Demand Validation Agent проверяет реальный интерес аудитории к товару через контролируемый эксперимент в соцсетях, прежде чем система рекомендует закупку.

Дизайн модуля исследован и предложен ChatGPT (сентябрь 2026), проверен и принят после независимой проверки фактов.

---

# Основные задачи

- генерировать пробный short-form видео-контент с товаром (Tier A: дешёвый скрининг; Tier B: профессиональная эскалация для топ-кандидатов);
- публиковать контент через официальные API платформ (TikTok Content Posting API, Instagram Professional Account API) на отдельные экспериментальные аккаунты — не на аккаунты пользователя и не через bot-farm/неавторизованную автоматизацию;
- собирать метрики через официальные API (views, reach, likes, comments, shares);
- вычислять относительные, нормализованные по когорте сигналы (percentile по платформе/категории/аккаунту), а не абсолютные пороги;
- принимать решение об эскалации с Tier A на Tier B на основе Early Signal Score;
- выдавать финальный вердикт: confirmed / weak / insufficient_data, с confidence и evidence.

---

# Архитектура (Tier A / Tier B)

## Tier A — дешёвый скрининг

- Провайдеры: дешёвые image-to-video API (например, недорогие модели через агрегаторы наподобие fal.ai/Replicate), не Creatify/HeyGen free-tier (это ручные студийные инструменты, не пригодные для массовой автоматической генерации через API).
- Короткое видео (5-8 сек), низкое/среднее разрешение, минимальный prompt.
- Цель: не "красивый ролик", а дешёвый сигнал "есть ли ранний интерес".

## Tier B — профессиональная эскалация

- Только для ~15-20% кандидатов, показавших сильный Early Signal Score на Tier A (точный процент — открытый вопрос, см. ниже).
- Провайдеры: Creatify API (product-centric creative), HeyGen (presenter/avatar), при необходимости Runway.
- Более длинный, качественный ролик, полноценный demand test.

Tier B — не новый независимый эксперимент, а продолжение того же DemandExperiment (parent/child через tier_parent_experiment_id).

---

# Calibration (обязательный элемент)

Прежде чем доверять Tier A как надёжному скринингу, система должна периодически прогонять calibration set (10-20 товаров через Tier A И Tier B одновременно) и измерять Tier-A → Tier-B predictive correlation.

Пока calibration_status != validated — результаты Tier A считаются только screening evidence, не окончательным доказательством отсутствия спроса.

Это защищает от false negative: слабый результат Tier A может объясняться низким качеством дешёвого рендера (watermark, артефакты), а не реальным отсутствием интереса к товару.

---

# Аккаунты — обязательное ограничение

Тестовые аккаунты — это отдельные, легитимные аккаунты, авторизованные через официальный OAuth/API каждой платформы.

СТРОГО ЗАПРЕЩЕНО:

- массовое автоматическое создание аккаунтов ("bot farm");
- искусственная накрутка лайков/комментариев/подписчиков;
- обход enforcement платформ.

Это прямо запрещено Terms of Service TikTok и Instagram/Meta и является реальным юридическим риском, а не вопросом технической осторожности.

Продающий/брендовый аккаунт (для реальных продаж после подтверждения спроса) — отдельная сущность от тестовых аккаунтов.

---

# Compliance Gate (обязательный этап перед публикацией)

Перед публикацией любого контента проверяется:

- AI disclosure — маркировка AI-сгенерированного контента (TikTok is_aigc, Instagram is_ai_generated), включая соответствие требованиям EU AI Act (Article 50) для рынков, где это применимо;
- asset rights verification — используемые фото/видео товара должны иметь подтверждённые права (от поставщика или сгенерированы AI с нуля), НЕ скопированы с чужих листингов/маркетплейсов без разрешения;
- platform policy check.

Публикация без прохождения Compliance Gate не допускается.

---

# Формат результата

DemandExperiment record с полями: tier, creative, publication, observation (time-series snapshots), early_signal (percentile-based score), escalation (trigger + metrics), compliance, calibration, result (classification + confidence).

Полная JSON-схема — в отдельной технической документации модуля (за пределами данного контракта).

---

# Границы ответственности

Demand Validation Agent НЕ должен:

- принимать финальное решение о закупке (это Business Manager);
- использовать искусственную накрутку метрик;
- публиковать контент, не прошедший Compliance Gate;
- интерпретировать сырые метрики без нормализации по когорте (platform + category + account + время).

---

# Передача результата

Demand Validation Agent → Business Manager (для финального решения, Workflow Этап 8).

Результат сохраняется в Knowledge Base вместе с остальной историей анализа товара (_Analysis/).

---

# Открытые вопросы

1. Точный процент эскалации (15-20% — начальная гипотеза, требует калибровки).
2. Точные веса Early Signal Score (view velocity, engagement velocity, share/comment rate, acceleration) — кандидаты на признаки, веса не валидированы.
3. Выбор конкретного дешёвого провайдера для Tier A — требует бенчмарка на реальных товарах, не зафиксирован окончательно.
4. Бюджет на платные API (Creatify/HeyGen для Tier B) — требует решения пользователя.
5. Минимальный размер выборки, при котором percentile становится статистически устойчивым — не определён.
