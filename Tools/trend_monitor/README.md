# Радар трендов

Раз в сутки (и по кнопке) собирает растущие поисковые запросы по всему миру и присылает короткий список в Telegram.

## Что радар делает и чего не делает

- Находит **подсказки**: что растёт в поиске. Это не проверенные товары.
- Ничего не покупает, не пишет поставщикам, не тратит деньги.
- Если источник данных сломался, присылает сообщение о сбое. Тишина означает «новых трендов выше порога нет».
- Проверка поставщика, маржи и спроса остаётся за системой и за решением человека.

## Как устроен

- `run.py` — движок: собирает, убирает повторы, отправляет.
- `sources/` — источники данных. Новый источник = новый файл, имя вписывается в `config.json` («вилка в розетку»).
- `config.json` — темы поиска, порог роста, сколько записей в день.
- `notify.py` — отправка в Telegram.
- Память о уже присланном: `Knowledge_Base/_Radar/seen.json`.
- Запуск по расписанию: `.github/workflows/trend_radar.yml`.

## Настройка (один раз)

В GitHub: репозиторий, Settings, Secrets and variables, Actions. Добавить два секрета:
- `TELEGRAM_BOT_TOKEN` — токен бота из @BotFather;
- `TELEGRAM_CHAT_ID` — номер чата, куда слать.

## Проверено / не проверено

- Проверено: выбор кандидатов, защита от повторов, сообщение о сбое (на тестовых данных).
- НЕ проверено: живой запрос к Google Trends и отправка в Telegram. Это можно проверить только на GitHub, ручным запуском.
- Риски: используется неофициальная библиотека pytrends, Google может ограничивать запросы или менять формат. Радар сообщит о сбое.
- Данные Google Trends показывают интерес в поиске, а не продажи.
